When the [built-in modes](./built-in-modes) don't fit, build a custom strategy pipeline. Define which content to reduce, how to reduce it, and when each strategy fires.

## Strategy pipeline

Strategies run as an ordered pipeline. Each strategy sees the output of the previous one, so order determines priority. If two strategies target the same content, the first one to shrink it below the next strategy's block threshold wins.

The SDK always appends an emergency truncation strategy as the final step. It only fires when the context window is still overflowing after all user strategies have run.

<Tabs>
<Tab label="Python">

```python
from strands import Agent
from strands.experimental.context_manager import Offload

agent = Agent(
    context_manager={
        "strategies": [
            Offload.truncate("tool_results").when(
                block_threshold=2000,
            ),
            Offload.summarize("*").when(
                utilization=0.8,
                preserve_recent=4,
            ),
        ],
    },
)
```

## Offload builder

The `Offload` namespace exposes three methods. Each returns a builder. Chain <Syntax py=".when()" ts=".when({})" /> to add [conditions](#conditions) and get the strategy; the SDK rejects a builder in the pipeline without it.

## Conditions

Conditions passed to <Syntax py=".when()" ts=".when({})" /> set when a strategy fires, what it acts on, and which messages it protects.

### Condition values

A number is a count in the condition's unit, and a `"N%"` string is a share of the whole.

| Condition | Number | `"N%"` string | Decimal |
|-----------|--------|---------------|---------|
| <Syntax py="utilization" ts="utilization" /> | Whole number above 1: fires at that many conversation tokens | Up to `"100%"`: fires at that share of the context window | Above 0, up to 1: same as `"N%"` (`1.0` is a full window) |
| <Syntax py="block_threshold" ts="blockThreshold" /> | Whole number: acts on blocks over that many tokens | Up to `"100%"`: acts on blocks over that share of the context window | Not accepted |
| <Syntax py="preserve_recent" ts="preserveRecent" /> | Whole number: keeps that many of the newest matching messages | Below `"100%"`: keeps that share of the newest matching messages | Below 1: same as `"N%"` |

<Syntax py="utilization" ts="utilization" /> only gates when a strategy fires. <Syntax py="preserve_recent" ts="preserveRecent" /> only protects the newest matching messages. Shares of the context window resolve against <Syntax py="context_window_limit" ts="contextWindowLimit" />, or the [default window size](./context-estimation) when it is unset.

### Granularity

The target and <Syntax py="block_threshold" ts="blockThreshold" /> decide whether a strategy acts on whole messages or on individual blocks. Old messages are those outside <Syntax py="preserve_recent" ts="preserveRecent" />, excluding the first message and pinned messages.

| Method | Target `"*"` without <Syntax py="block_threshold" ts="blockThreshold" /> (messages) | Other target or <Syntax py="block_threshold" ts="blockThreshold" /> set (blocks) |
|--------|------------------|-------------------|
| Drop | Removes old messages and inserts a `[Dropped: N messages]` marker | Replaces each block with a `[Dropped]` stub |
| Truncate | Keeps the head and tail of the old messages within <Syntax py="preview_tokens" ts="previewTokens" /> and elides the middle | Replaces each block with a preview |
| Summarize | Summarizes each contiguous run of old messages | Summarizes each block |

A message strategy needs <Syntax py="utilization" ts="utilization" /> or <Syntax py="preserve_recent" ts="preserveRecent" />; without either, <Syntax py=".when()" ts=".when({})" /> raises an error.

A block strategy acts on blocks over <Syntax py="block_threshold" ts="blockThreshold" />. When it is unset, drop and summarize act on every matching block, and truncate defaults it to <Syntax py="preview_tokens" ts="previewTokens" />. Truncate skips blocks it already truncated. A block strategy with neither <Syntax py="utilization" ts="utilization" /> nor <Syntax py="preserve_recent" ts="preserveRecent" /> runs on every new message as it arrives. An empty <Syntax py=".when()" ts=".when({})" />, such as <Syntax py='Offload.drop("tool_result_errors").when()' ts="Offload.drop('toolResultErrors').when({})" />, acts on every matching block.

:::caution[Changes to conditions]
- `threshold` is renamed to <Syntax py="block_threshold" ts="blockThreshold" />.
- `Offload` methods return a builder that needs <Syntax py=".when()" ts=".when({})" />. A bare builder is not a strategy.
- Drop and summarize with a target other than `"*"` plus <Syntax py="utilization" ts="utilization" /> act on blocks, not whole messages.
- <Syntax py='Offload.drop("*")' ts="Offload.drop('*')" /> and <Syntax py='Offload.summarize("*")' ts="Offload.summarize('*')" /> with only <Syntax py="preserve_recent" ts="preserveRecent" /> act on whole messages.
- <Syntax py='Offload.truncate("*")' ts="Offload.truncate('*')" /> without <Syntax py="block_threshold" ts="blockThreshold" /> keeps the head and tail of the old messages and elides the middle.
- The <Syntax py='"overflow_protection"' ts='"overflowProtection"' /> preset drops the oldest messages instead of truncating them.
:::

## Targets

Targets specify which content a strategy applies to.

<Tabs>
<Tab label="Python">

| Target | Value |
|--------|-------|
| All content | `"*"` |
| Tool results | `"tool_results"` |
| Failed tool results | `"tool_result_errors"` |
| Assistant text | `"assistant_text"` |
| User text | `"user_text"` |
| Specific tools | `["tool::bash", "tool::read_file"]` |
| Exclude tools | `["!tool::bash"]` |

</Tab>
<Tab label="TypeScript">

| Target | Value |
|--------|-------|
| All content | `"*"` |
| Tool results | `"toolResults"` |
| Failed tool results | `"toolResultErrors"` |
| Assistant text | `"assistantText"` |
| User text | `"userText"` |
| Specific tools | `["tool::bash", "tool::readFile"]` |
| Exclude tools | `["!tool::bash"]` |

</Tab>
</Tabs>

Tool name lists use the `tool::` prefix. Prefix a name with `!` to exclude it (apply to all tools *except* the listed ones).

## Stash

The stash stores all message content on arrival as JSON, before any strategy runs. Truncated or summarized content can be retrieved on demand through the `retrieve_context` tool, which the SDK registers by default.

Stash uses in-memory storage by default. Configure it through the <Syntax py="stash" ts="stash" /> key:

- Omit or pass `true` for defaults (in-memory storage)
- Pass a config with a custom storage backend
- Pass `false` to disable stash entirely

<Tabs>
<Tab label="Python">

```python
from strands import Agent

# Disable stash and retrieval tool
agent = Agent(
    context_manager={
        "stash": False,
    },
)
```

## Emergency truncation

Every strategy pipeline ends with an emergency truncation strategy, appended automatically. It fires only when the context window is still overflowing after all user strategies have run. When it fires, it drops the oldest 20% of non-head messages.

Emergency truncation intentionally ignores pinned messages so an all-pinned overflow is still recoverable. Regular strategies respect pins.
