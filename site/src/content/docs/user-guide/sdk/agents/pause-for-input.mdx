An agent chooses and runs its own tools. Most calls are fine to run unattended, but a
few, such as deleting files or sending an email, should wait for a person to sign off.
Asking about every call wears people down until they approve without reading. The
`HumanInTheLoop` intervention handler, with its risk classifier turned on, asks only
about the calls that matter: a model rates each tool call, safe calls run, and risky
ones pause the agent until a person approves or rejects them.

## Pause risky tool calls

To have a person approve risky calls, add the handler with its classifier turned on.
This agent cleans up log files. Listing a directory is safe, so it runs. Deleting files
can't be undone, so the agent stops and asks first:

<Tabs>
<Tab label="Python">

```python
from strands import Agent, tool
from strands.vended_interventions.hitl import HumanInTheLoop


@tool
def list_files(directory: str) -> list[str]:
    """List the files in a directory."""
    return ["app.log", "app.log.1", "app.log.2"]


@tool
def delete_files(paths: list[str]) -> str:
    """Delete the files at the given paths."""
    return f"Deleted {len(paths)} files"


agent = Agent(
    tools=[list_files, delete_files],
    interventions=[HumanInTheLoop(classifier=True)],
    callback_handler=None,
)

result = agent("Delete the rotated logs in /var/log/app")

# The agent stops before each tool call the classifier rates risky
while result.stop_reason == "interrupt":
    responses = []
    for interrupt in result.interrupts:
        answer = input(f"{interrupt.reason} (y/n): ")
        responses.append(
            {"interruptResponse": {"interruptId": interrupt.id, "response": answer}}
        )
    result = agent(responses)

print(result)
```

Typical output, after answering `y`:

```
Approve "delete_files" — Deleting files is irreversible; logs may be needed.?
  Input: {"paths": ["/var/log/app/app.log.1", "/var/log/app/app.log.2"]} (y/n): y
Done! I've deleted the 2 rotated log files:
- `/var/log/app/app.log.1`
- `/var/log/app/app.log.2`

The current log file `/var/log/app/app.log` has been left intact.
```

Before each tool call, the classifier sends the tool name and input to a model and asks
whether the call needs approval. A call it rates risky doesn't run. Instead, the agent
returns with stop reason `interrupt` and one interrupt per paused call. Each
interrupt's reason is the approval prompt: the tool, why the classifier flagged it,
and the input.

Resume by invoking the agent with one interrupt response per interrupt. `y`, `yes`, or
<Syntax py="True" ts="true" /> approves the call. Any other response cancels it, and
the agent learns the call was rejected so it can tell the user or try something else.
Keep resuming until the stop reason is no longer `interrupt`, because the agent can
make more risky calls after you approve one.

The classifier fails closed: if its model call errors, the tool call waits for
approval. It runs on the agent's model, or on the
[auxiliary model](../model-providers/index.md#auxiliary-model) when you set one.
Without the classifier, every tool call pauses.

In a web service, the request that pauses the agent and the request that resumes it
are usually different. Use a [session manager](./session-management.md) to restore the
agent between them.

## Prompt at the terminal

For a CLI, let the handler ask the question itself. Set
<Syntax py='ask="stdio"' ts="ask: 'stdio'" /> alongside the classifier and the handler
prompts in the terminal and waits for the answer. The agent never stops with an
interrupt, so the resume loop goes away.

## Skip the classifier for known-safe tools

Each classified call costs a model request. When you already know a tool is safe, list
it in <Syntax py="allowed_tools" ts="allowedTools" /> and it runs without a
classifier call or a prompt. With
<Syntax py='allowed_tools=["list_files"]' ts="allowedTools: ['list_files']" />, only
calls to `delete_files` reach the classifier.
